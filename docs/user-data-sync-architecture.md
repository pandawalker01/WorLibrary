# 用户数据与原书跨设备同步设计

> 状态：**个人云书库 P0 已有 manifest、私有对象存储、分块恢复、配额和删除墓碑代码；真实 Supabase/R2 上传、恢复、RLS 和对象访问均为 NOT VERIFIED**。`private-r2-v1` 不是应用层加密或端到端加密。

## 内测 MVP 截止线

本轮内测只实现稳定邮箱账户之间的书架元数据、阅读进度、摘录和必要偏好同步，并以真实双浏览器 profile 验收为上线条件。用户自导入 EPUB/PDF、封面二进制、全文索引和离线正文当前仍严格留在导入设备；新设备当前仅显示“需重新导入原书”，不能以元数据打开阅读器。匿名会话不排队、不上传。该限制仅是内测的安全降级，不能作为正式产品的用户承诺。

对象分块、配额、下载恢复、账户删除、Google/Apple 登录和匿名迁移仍属于内测后的阶段 B/C。正式首发的优先级已经调整：已登录用户的自导入书必须进入个人私有云书库，并在另一设备登录后无需重新导入即可访问；严格端到端加密与恢复码作为可选高级隐私模式推进。本文件后续有关文件访问的章节是已批准的目标设计，不得被解读为当前已经部署或可恢复用户原书。

## 1. 决策与目标

已登录用户的个人图书馆不应只留在一个浏览器中。WorLibrary 的正式体验目标是：用户在任意新设备登录同一账户后，书架、阅读位置、摘录、笔记、阅读统计、偏好及其已导入原书自动可访问；不要求重新导入、手动传文件或“恢复”操作。文件可在首次打开时无感按需下载，也可对最近阅读内容后台缓存。

客户体验优先并不等于静默上传：首次从本机书库切换为登录账户的云书库时，产品必须以一次清晰、可跳过的说明征得用户同意，说明个人文件会进入私有云书库、当前用量、删除入口与合法副本责任。完成一次选择后，后续导入自动进入该账户的云书库；用户可在设置中暂停或关闭原书同步。

本设计采用“本地优先 + 结构化数据 Supabase + 加密文件对象存储”的三层模型：

```text
设备本地（可离线阅读）
  ├─ EPUB/PDF 原文件、封面、全文索引
  ├─ 本地写入队列与加密文件缓存
  └─ 立即更新的进度/摘录
            │ 登录后后台同步
            ▼
Supabase Postgres（按 user_id + RLS 隔离）
  ├─ 书架元数据、版本、进度、摘录、笔记、统计、设置
  └─ 文件清单、加密对象版本、上传状态与删除墓碑
            │ 仅服务端签发短期上传/下载能力
            ▼
私有对象存储（Cloudflare R2，非公开桶）
  └─ 用户加密后的 EPUB/PDF 分块（高级隐私模式为端到端密文）
```

### 1.1 明确边界

- **用户导入内容**：登录账户完成一次“同步到个人云书库”选择后自动排队上传；另一设备登录后直接显示并可按需打开，不要求重新导入。未登录、用户明确暂停或关闭云书库时才只留在本机。
- **平台内容**：继续使用平台许可、权益和私有 R2 交付链路，绝不混入用户备份桶或用户文件表。
- **外部目录收藏**：只同步书目、来源链接和访问状态，不上传第三方正文。
- **默认隐私模式（无感访问）**：文件始终经 HTTPS 与私有对象存储加密，并按账户 RLS/授权隔离；密钥由受控服务托管，以支持新设备仅登录即可访问。它不是端到端加密，必须在隐私说明中如实陈述。
- **高级隐私模式（端到端加密）**：R2 中只保存客户端加密后的密文，服务端不能读取正文；新设备首次访问需一次恢复码或已登录设备确认。不得把这一额外动作伪装为无感登录。
- **匿名会话不能启用云备份**：必须先升级为稳定账号。匿名会话的本地数据可在将来受控升级时迁移至该账号，但不能作为长期备份身份；**当前版本尚未实现该迁移**，匿名试用不创建同步队列或上传元数据。

### 1.2 以用户体验为先的设计准则

参考成熟个人阅读器的交互预期，而不复制其界面或品牌：同一账户的书架应跨设备一致；用户不应理解对象存储、manifest、分块或密钥才能继续阅读；网络、缓存和上传状态必须可见但不能阻塞开始阅读。

1. **一次同意，不重复劳动**：首次说明云书库范围后，后续导入自动同步；新设备只需登录，不要求重新上传、重新导入或手工“恢复”。
2. **先可见、后传输**：新设备先呈现书架与最近阅读进度；打开未缓存的书时立即给出可理解的准备状态，后台按需恢复，避免登录时全量下载。
3. **用户始终可控**：可暂停同步、限制 Wi-Fi、查看用量、仅移除此设备副本或彻底删除云端副本；这些动作不应隐藏在开发者设置中。
4. **如实说明隐私模式**：默认托管加密优先无感访问；高级端到端加密优先服务端不可读。任何额外恢复步骤必须在用户切换模式前说明。
5. **失败可恢复，不丢书架**：断网、空间不足、配额不足和后台上传失败都保留书架项目、显示下一步，并能自动或一键续传；不得回退到“请重新导入”。

## 2. 当前状态与缺口

现有浏览器本地库使用 IndexedDB/OPFS 保存导入文件、书架、进度和摘录；`src/lib/sync.ts` 保留的旧全表 REST 实现已被客户端关闭，不能作为任何跨设备同步的验收依据。IndexedDB v5 新增的 `metadata-sync-outbox` 只保存账户隔离、已验证的 metadata mutation 意图，独立于 `books` 与 `book-blobs`；`src/lib/metadata-sync-engine.ts` 按创建顺序 flush，使用精确 lease 确认与 revision 重基，并以受控 RPC 分页拉取变更。网络错误保留待处理项，在线状态下做有限指数退避，离线后由网络恢复事件重放。IndexedDB v6 另设 `remote-book-metadata-shadows`：它按账户与来源 `editionId` 保存受控 change feed 的书名、作者、语言、进度、位置、文件元数据、封面色及服务器 revision/sequence；每条记录固定为 `needsReimport`，既不含原书字节、cover data URL、对象键/URL 或正文，也绝不构造成 `StoredBook`。`src/lib/metadata-sync-edition-shadow.ts` 是该 store 唯一允许的 edition feed 投影器：仅接受前述白名单字段与 `epub`/`pdf` 文件类型，拒绝未知字段、数据 URL、对象定位和正文；未知 entity 不触碰 store，由 change-feed 协调器决定游标语义。`src/lib/device-registration-session.ts` 已能在稳定账户、调用方确认远端配置后，为当前浏览器读取或创建随机 UUID 并调用受控设备注册 RPC；它不会在匿名或未配置状态触碰本地设备标记或网络，也不把用户/书籍数据写入设备标记。`src/lib/metadata-sync-coordinator.ts` 将注册、flush、pull、投影和 revision/cursor 持久化组合为一次有界运行；遇到未知/不安全 entity、outbox 阻塞或 cursor 写入失败时停止，不假装完成。`src/App.tsx` 已接入稳定账户启动、书架/进度/摘录/必要偏好写入、回前台/恢复联网同步和账户失效；阅读偏好缓存按账户隔离，登出与账户切换会取消旧账户运行及重试。实时双浏览器 Supabase/RLS 验收尚未执行，因此当前仍不能视为通过跨设备发布门槛。未完成项：

受控 metadata RPC 的 edition payload 白名单为书名、作者、语言、进度、位置、文件名/类型/大小和安全封面色；阅读进度仅含版本 ID、进度与位置；偏好仅限 `reader.layout` / `reader.language`。文件名、类型和大小属于书目 metadata，不是文件传输。EPUB/PDF 或封面二进制、对象键、URL 和整本正文都不得发送；选区文本仅通过私有摘录 RPC 发送。真实 staging 首次 edition upsert 曾因 `controlled_sync_payload_has_forbidden_key` 未覆盖 JSON 标量 leaf 而抛 `case not found`；migration `0016_metadata_sync_scalar_payload_guard.sql` 增加了标量分支并有本地契约测试覆盖，但截至 2026-10-28 尚未部署到 staging，修复后真实同步和 RLS 验收仍 BLOCKED。

1. 原 EPUB/PDF、封面和全文索引尚未上传；新设备目前无法自动访问原书。
2. `works`、阅读统计、联网收藏和版本关联尚未形成完整同步闭环。
3. 复杂并发冲突的字段级策略、文件版本和面向用户的可观测重试状态仍未实现；本轮只保证网络失败保留队列并自动有限重试。
4. 个人云书库开关、存储额度、上传、透明按需下载、账户删除、默认托管加密与高级端到端加密尚未实现。

因此，在这些能力完成前，界面必须继续说明“本地优先；导出阅读数据用于备份”，不能承诺跨设备访问；一旦个人云书库发布，产品文案必须承诺“登录后直接访问”，而非“重新导入”。

### 3.1 用户文件的永久删除

用户从书库选择“仅移除此设备的副本”时，不影响个人云书库；选择“从所有设备和云端删除”时，客户端写入墓碑，服务端立即停止该账户的文件访问并异步删除所有对象分块。对象删除完成前，UI 显示“删除处理中”。账户删除需在法定保留例外外删除全部用户数据、文件清单与对象，并记录不含正文的操作审计。

## 4. 远端数据模型

现有 `works`、`editions`、`reading_progress`、`highlights`、`user_settings` 与 `devices` 继续以 `user_id = auth.uid()` RLS 隔离。新增迁移必须向前兼容，并增加以下表：

```text
user_file_manifests
  id, user_id, edition_id, plaintext_hash, plaintext_size, media_type,
  encryption_version, wrapped_dek, wrapped_dek_nonce, key_envelope_id,
  chunk_count, active_version, upload_state, idempotency_key,
  deleted_at, created_at, updated_at

user_file_chunks
  id, user_id, manifest_id, manifest_version, chunk_index, cipher_hash,
  ciphertext_size, nonce, object_key (server-only), uploaded_at, deleted_at

sync_changes
  id, user_id, device_id, entity_type, entity_id, operation_id, operation,
  entity_revision, base_revision, payload_ciphertext, occurred_at, tombstone_payload

user_storage_quotas
  user_id, included_bytes, used_bytes, reserved_bytes, updated_at

user_key_envelopes
  id, user_id, envelope_version, recovery_kdf, kdf_salt, kdf_parameters,
  wrapped_account_root_key, wrap_nonce, created_at, revoked_at
```

规则：

- 浏览器可读写自己的书架/进度/摘录等业务行，但 `title`、`author`、`file_name`、封面、阅读位置、摘录、笔记、统计、AI 缓存与文件 hash 都必须按所选隐私模式加密保存：默认个人云书库使用托管加密，高级隐私模式才使用端到端加密 payload。服务端不提供用户私人书架全文搜索；搜索在已解锁客户端本地完成。
- 浏览器**不能**直接读写 `user_file_chunks.object_key`、配额、服务器侧删除状态、key envelope 或其他设备数据。
- 文件分块的对象键只由受控服务端或 Worker 解析；浏览器只能拿到单用途、极短期的上传/下载请求能力，且不得写入 IndexedDB、日志或 URL 查询参数。
- `sync_changes` 是逻辑变更日志，不保存全文、文件名以外的敏感正文或 AI 选区；同步确认后可按保留期压缩。
- 所有写入需附带设备 ID、UUID `operation_id` 和每实体单调递增的 `entity_revision`；RLS、唯一约束与事务负责拒绝跨用户、重复操作、重复分块和陈旧版本覆盖。`(manifest_id, manifest_version, chunk_index)`、`(user_id, operation_id)` 与 `(user_id, idempotency_key)` 必须唯一。

## 5. 加密与密钥管理

### 5.1 默认：托管加密，支持无感跨设备访问

默认个人云书库必须满足“新设备登录即可读”，因此使用受控服务托管的每账户加密密钥：文件传输使用 HTTPS，R2 保持私有，静态对象与密钥均受云平台加密；Worker 每次读取时验证 Supabase JWT、账户所有权、设备状态和删除墓碑后才允许该账户的短期读写能力。浏览器不拿到 R2 长期凭据、对象键或跨账户访问能力。

这一模式的优点是用户无需在新设备输入恢复码、联系旧设备或重新导入；代价是受控服务在严格授权、审计和最小化运维流程下技术上具备解密能力。产品必须把它称为“私有云书库/托管加密”，不得称为端到端加密。

### 5.2 高级隐私：端到端加密方案

1. 客户端为每个用户备份版本生成随机 256-bit 数据密钥（DEK）。
2. EPUB/PDF 在客户端分块（建议 8 MiB），每块使用 AES-256-GCM 加密，独立随机 IV；上传密文、cipher hash、大小和分块序号。
3. 文件明文 SHA-256 只用于用户自身去重与恢复校验；不得作为公共可枚举索引或跨用户去重键。
4. DEK 以用户主密钥（KEK）包装；Supabase 与 R2 仅保存包装后的 DEK、加密算法版本和必要元数据，永远不保存明文 DEK。

### 5.3 高级隐私模式的主密钥与恢复

WorLibrary 使用魔法链接，不假定用户具有可用于派生密钥的账户密码。启用云备份时，客户端生成随机 256-bit **账户根密钥（ARK）** 与高熵恢复码：

1. ARK 只保存在已解锁设备的安全存储中：Web 使用不可导出的 WebCrypto `CryptoKey` / 包装后的 IndexedDB 记录，桌面/移动使用系统 Keychain/Keystore；不得放入 localStorage。
2. 恢复码经经过安全评审的 KDF（首选 Argon2id；WebCrypto 受限平台必须使用参数受控的 PBKDF2-SHA-256）派生 KEK，包装 ARK，形成 `user_key_envelopes` 中唯一可跨设备恢复的密钥信封。
3. 新设备先完成 Supabase 魔法链接登录，再输入恢复码解开 ARK，之后才可解开各文件 DEK 并下载密文分块。另一台已解锁设备也可通过短时、双端确认的设备配对流程添加新设备；该流程不得把 ARK 放入 URL、推送内容或服务端日志。
4. 用户可创建新的恢复码；轮换会新增 envelope 并废弃旧 envelope。被盗设备可从设备列表撤销，其 JWT 刷新与后续文件能力必须立即失效；已下载的本地密文/明文无法被远程抹除，应在产品中明示。

遗失恢复码且没有另一台已解锁设备时，平台无法恢复处于高级隐私模式的用户原书。该限制必须在开启该模式前明确展示。默认托管加密模式不要求恢复码，但也不得被标为端到端加密。

> 具体 KDF 参数、WebCrypto 兼容性、密钥轮换和原生安全存储必须在实现前完成安全评审与跨端互操作测试；不得自行发明密码算法。

## 6. 同步协议与冲突策略

### 6.1 登录、初始化和上传

```text
本地匿名/已登录书架
  → 用户登录或升级账号
  → 首次仅一次地确认“同步到个人云书库”
  → 以不透明游标拉取云端 change feed / snapshot watermark
  → 合并元数据与阅读数据
  → 后续自导入书自动排队、分块并上传到私有对象存储
  → 服务端原子提交 manifest，再把版本标为 active
新设备登录
  → 自动恢复书架、进度和摘录
  → 书籍可见且可打开；首次打开透明地按需下载、校验并缓存
```

上传中断不能暴露或激活半份文件：未完成 manifest 仅为 `uploading`，过期分块由后台回收。`initiate`、每块上传、`complete` 与取消均需 UUID 幂等键；同一 `manifest_version` 只能从 `uploading → verifying → active` 单向迁移。上传完成后，新设备通过 manifest 获取受控下载能力，逐块校验、解密并写入其本地 OPFS/沙盒；该过程不得要求用户重新选择原书文件。网络或配额不足时显示可恢复状态与“稍后继续”，但不丢失书架项目。

### 6.2 合并规则

| 实体 | 冲突策略 |
| --- | --- |
| 阅读位置/进度 | 先比较服务端分配的 `entity_revision`，再用服务端 `occurred_at` 解决同 revision 的竞争；客户端时间只用于展示。若两个设备都前进，保留更靠后的有效位置，并保留另一条变更供诊断。 |
| 摘录、笔记 | 以稳定 ID 合并；删除使用墓碑优先于旧更新；同一笔记并发编辑保留两个修订版本，提示用户选择。 |
| 书架与版本元数据 | 以服务端 revision 合并；标题/作者人工编辑冲突保留双方加密修订并提示。 |
| 原文件 | 文件内容以 `content_hash + manifest version` 标识，不进行字节级合并；同名不同内容并存为两个版本。 |
| 删除 | 墓碑跨设备至少保留 30 天，防止离线旧设备重新上传已删除内容。超过保留期返回的旧设备必须先全量 snapshot 再写入；其陈旧操作拒绝且不允许 resurrection。 |

本地写入永远先完成，网络失败进入持久化队列并采用带抖动的指数退避；不会因同步失败阻塞翻页、划线或导入。

## 7. 服务端与对象存储接口

浏览器不直接获得 R2 长期凭据。新增 Worker API 需要使用已验证 Supabase JWT，并在每个请求验证 `user_id` 与 manifest 的所有权：

| 路由 | 职责 | 安全要求 |
| --- | --- | --- |
| `POST /api/user-files/initiate` | 创建上传会话、原子预留配额、返回分块上传能力 | 验证 JWT issuer/audience/expiry/JWK、登录、设备未撤销、配额、文件类型/大小限制、幂等键、无对象键泄露 |
| `POST /api/user-files/:id/chunks/:index` | 接收或代理单块密文 | 能力绑定 user/device/manifest/version/index/hash/单次有效期；顺序/哈希/大小校验、`no-store` |
| `POST /api/user-files/:id/complete` | 核验所有分块并激活 manifest | 原子提交、审计、失败关闭 |
| `GET /api/user-files/:id/chunks/:index` | 受控下载单块密文 | 每次 JWT/RLS 所有权校验、范围/速率限制、`private, no-store` |
| `DELETE /api/user-files/:id` | 创建全局删除墓碑、撤销未使用能力与异步清理任务 | 幂等、恢复窗口、部分失败重试与可见状态 |
| `GET /api/sync/changes` | 拉取当前用户变更 | 不透明游标、snapshot watermark、分页、无正文/对象键；游标过期时要求全量 snapshot |

对象存储使用与平台内容分离的私有 bucket，例如 `USER_BACKUPS`；禁止 public bucket、静态域名、跨用户对象键猜测、CDN 公共缓存和浏览器直连长期 token。服务端日志只记录请求 ID、用户/设备匿名化标识、字节数和结果，不记录正文、密钥、对象键或恢复码。

## 8. 配额、成本与产品交互

- 首次开启个人云书库时显示将要同步的范围、目前已用、本次预计上传量、套餐/免费额度、仅 Wi-Fi 选项、暂停/删除入口和合法副本责任；不能在每台新设备重复要求确认或重新导入。
- 默认可设置单文件上限、总配额与月度上传限制；服务端在 `initiate` 的同一事务中预留字节，完成/取消/超时回收后结算。预留必须有到期时间，且同用户同 hash 的已存在密文版本才可复用；不得跨用户去重。
- 用户可以分别选择：同步阅读数据、暂停原书云书库、仅 Wi-Fi、自动缓存最近阅读书籍、删除云端副本但保留本机文件，以及是否进入高级端到端加密模式。
- 新设备先恢复书架与进度，再按需透明下载书籍；不能因为登录就自动消耗大量流量或存储空间。首屏应立即显示可阅读状态和下载进度，用户点击书籍不应看到“请重新导入”。
- 文件本身可能受版权或服务条款限制。开启备份仅面向用户拥有合法副本的个人私有备份，不代表平台获得分发权，也不允许共享、公开链接或跨账户转让。

## 9. 分阶段实施与验收

### 阶段 A：完整元数据同步

补齐现有同步表、变更日志、设备 ID、阅读统计、世界书库收藏、设置、删除墓碑与冲突 UI；不上传原文件。

验收：两台设备登录同一账号后，进度、摘录、笔记、统计与书架元数据可恢复；网络中断不丢本地写入；不同账号互不可见。

### 阶段 B：个人云书库与无感跨设备访问

实现私有对象桶、manifest、托管加密、可恢复上传、额度预留、新设备透明按需下载、设备撤销与账户删除。开始编码前先完成协议附录：JWT 验证、对象访问能力、状态机、删除/回收 SLA、RPO/RTO、威胁模型及托管密钥轮换。

验收：用公开测试 EPUB/PDF 验证上传中断续传；新设备仅登录后书架自动出现、无需重新导入即可打开并按需恢复；私有对象不可直接访问；清除新设备数据后再次登录仍可恢复。

### 阶段 C：高级隐私、跨端与运营完善

为选择高级隐私模式的用户实现恢复码、WebCrypto 分块端到端加密与已登录设备确认；为 Tauri/Capacitor 接入安全密钥存储与原生文件沙盒；增加配额、成本告警、账号删除、密钥轮换、数据导出、审计与灾难恢复演练。

验收：Web、桌面、iOS/iPadOS、Android 均能在网络切换、离线编辑与并发修改后稳定恢复；账户删除在承诺期限内清除结构化数据与加密对象。

## 10. 上线前安全与 QA 清单

- 两个真实账号及匿名会话的 RLS 隔离测试；不得越权读取 manifest、分块或进度。
- 对象桶维持私有；浏览器、公开 URL、日志和错误响应中均无长期对象键、密钥、恢复码或正文。默认托管加密与高级端到端加密必须分别验收，且对外文案不得混用。
- 上传完整性：块大小、总大小、cipher hash、分块数和 manifest 状态均校验；中断、重试、重复和乱序请求不可生成错误 active 文件。
- 恢复完整性：明文 hash、媒体类型和解密认证标签失败时拒绝导入，不污染本地书架。
- 冲突/删除：离线设备、墓碑、恢复窗口、并发笔记编辑和相同文件名不同内容均有自动化回归。
- 费用与滥用：配额预留、速率限制、异常大文件、重复上传、账号删除和对象回收均可观测。
- 平台内容与用户备份完全隔离：不同 bucket、不同权限、不同 API 与不同审计流。
- 威胁模型覆盖恶意客户端、XSS、被盗 JWT/恢复码、替换或回滚密文、失联设备和对象删除失败；验证密钥轮换后旧文件仍可读取，并记录灾难恢复 RPO/RTO。

## 11. 尚待产品确认的项目

## 12. P0 网关实现与运行约束

`0015_private_user_file_gateway.sql` 是 `0014` 的后继，必须按编号执行。它只向 `service_role` 授权上传、分块记录、完成和删除 RPC；authenticated/anon 不能读分块或对象键。Worker 同时需要私有 `USER_BACKUPS`、`SUPABASE_URL`、`SUPABASE_ANON_KEY` 和 Secret `SUPABASE_SERVICE_ROLE_KEY`。同一 idempotency key 重新 initiate 会返回已上传索引，客户端跳过它们继续；完成前 manifest 不会 active。恢复逐块经 Worker 重验账户与 active 状态，不提供下载 URL。

删除顺序是 tombstone/标记 deleting、删除 R2 对象、标记 deleted/结算配额。R2 删除失败必须保留 deleting 与 tombstone 并由受控重试任务继续；不能以删除表或 tombstone 作为回滚。真实两账户/两设备验收完成前，任何用户文案仍不得称“同步完成”。
