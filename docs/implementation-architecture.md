# WorLibrary 可行性与实现架构

> 目标：让用户在本地导入合法拥有的多语言电子书，离线阅读，并在划线后获得其理解语言的翻译与解释。

## 1. 结论

项目在技术上可行，推荐采用 **本地阅读器 + Cloudflare 边缘 API + Supabase 元数据服务** 的模式：书籍原文件与即时离线体验留在浏览器；Cloudflare 负责公共目录检索、AI/OCR 网关和安全边界；Supabase 负责账户与经明确验收的同步元数据。

首发应稳定支持 EPUB 与文本型 PDF。扫描 PDF、CBZ、MOBI 和自动译本对齐都可实现，但不应成为 MVP 的发布前提。

## 2. 总体架构

```text
                    用户浏览器（PWA）
      ┌──────────────────────────────────────────┐
      │ React + TypeScript：导入、阅读、划线、对照 │
      │ EPUB.js / PDF.js：解析与渲染               │
      │ Web Worker：后台解析，避免界面卡顿         │
      │ OPFS：原始书籍文件                         │
      │ IndexedDB：进度、划线、笔记、缓存、映射    │
      └───────────────────┬──────────────────────┘
                          │ 仅发送选区或当前页
      ┌───────────────────▼──────────────────────┐
      │ Cloudflare Worker：静态资源 + API           │
      │ 目录检索、缓存、限流、人机验证、额度、审计 │
      └───────────────┬──────────────┬───────────┘
                      │              │
          ┌───────────▼────────┐ ┌───▼─────────────┐
          │ Supabase            │ │ AI / OCR 服务   │
          │ Auth + Postgres     │ │ 翻译、解释、识别 │
          │ 用户、额度、同步元数据│ └─────────────────┘
          └────────────────────┘
```

## 3. 客户端：用户真正的图书馆

### 本地保存

- **OPFS** 保存 EPUB、PDF、CBZ 等较大的原始文件。
- **IndexedDB** 保存作品、版本、阅读位置、划线、笔记、AI 解释缓存与对齐关系。
- **Service Worker** 缓存应用资源与近期阅读内容，实现离线打开。
- **Web Worker** 解析目录、提取 PDF 文本和建立索引，避免占用主线程。

默认情况下，书籍文件不上传；断网时仍能继续阅读已导入的内容。

### 格式支持边界

| 格式 | MVP 支持度 | 实现方式 | 说明 |
| --- | --- | --- | --- |
| EPUB | 高 | EPUB.js、CFI 锚点 | 首发主力格式。 |
| 文本型 PDF | 高 | PDF.js、文本层 | 可选区、划线与解释。 |
| 扫描 PDF | 中 | 页面渲染后按需 OCR | 识别结果需允许用户校对。 |
| CBZ | 中低 | 图片序列阅读、按需 OCR | 不承诺精确的文本锚点或段落对齐。 |
| MOBI | 低 | 转换为 EPUB 或实验性解析 | 不宜承诺首发稳定支持。 |

## 4. 数据模型

不要将单个文件直接视为一部作品。一个作品可有多个语言版本，各版本拥有独立进度与笔记。

```text
Work（作品）
 ├─ Edition（具体版本 / 本地文件）
 │   ├─ ReadingPosition（独立阅读进度）
 │   ├─ Highlight（划线）
 │   └─ Note（笔记）
 ├─ Edition（另一种语言版本）
 ├─ Alignment（版本之间的章节或段落映射）
 └─ AIExplanation（选区、上下文、语言、模型版本、生成时间）
```

划线需要保存稳定锚点和恢复信息：EPUB 使用 CFI 与章节标识；PDF 使用页码、文本层坐标与文本；OCR 页面使用文字框坐标。同时保存少量前后文本，便于文件更新或解析变化后恢复定位。

## 5. 世界书库的数据源与版权边界

世界书库是“发现层”，不是未授权正文的分发层。它使用可插拔的目录适配器：每个适配器把来源返回的记录规范为来源、来源记录 ID、书目元数据、外部链接和可读性状态。当前启用 Open Library（恒为 `catalog_only`）和 Google Books（按 API 的 `viewability` 映射为 `catalog_only`、`preview` 或 `public_domain`）；用户点击后始终跳转至相应来源的原始页面。

```text
用户搜索
  └─ WORLD_CATALOG_SOURCES（已审核适配器注册表）
       └─ CatalogSource.search()
            └─ WorldBook { sourceId, sourceRecordId, sourceUrl, access }
                 ├─ catalog_only：仅展示书目与来源外链
                 ├─ public_domain：已验证公共领域来源的外部正文入口
                 └─ licensed_full_text / preview / borrow / purchase：按来源许可显示相应外部入口
```

新增来源前必须完成：书面或公开许可/服务条款核对、API 限流与缓存方案、来源归属展示、正文访问权判定、失败隔离和自动化验收。来源请求必须有独立超时；一个来源失败时保留其他成功来源的结果。不能因为作品标题、搜索词或某个来源声称“公共领域”就推断 WorLibrary 有正文分发权。不得接入、代理、镜像未获授权正文库，亦不得通过白名单、隐藏入口或个人权限绕过该边界。

联网收藏仅保存可重新发现该记录所需的元数据，使用 `sourceId:sourceRecordId` 去重；旧 Open Library 收藏在读取时迁移为 `open-library` / `catalog_only`。原始书籍文件始终只来自用户本地导入，或将来经过单独审核的合法正文来源。

### 平台书库与应用内阅读的交付边界

平台书籍与用户导入书籍必须使用不同的数据和交付链路。用户导入的二进制继续停留在本机 OPFS / IndexedDB；平台内容使用独立的 `catalog_works`、`catalog_editions`、`content_assets`、`access_policies`、`user_library_items` 与 `user_entitlements`。其中 `content_assets.object_key` 只对服务端可见，不能通过 Supabase 客户端权限或 Worker 策略接口暴露给浏览器。

```text
用户将条目加入我的书库
  ├─ local_import：本机 bookId，可离线阅读
  ├─ platform：平台 editionId，按地区策略与 entitlement 决定 download / stream / preview
  └─ external_catalog：来源与记录 ID，仅 external_reader / preview / catalog_only

阅读请求
  → Worker /api/reader/access 读取合规访问策略
  → 受限版本交给授权服务验证既有会话
  → Worker /api/reader/content 每次请求再次验证同一权益
  → 私有 R2 仅以允许的 EPUB/PDF Range 响应提供正文字节
  → 平台阅读器按已接入的安全渲染器显示内容；未接入时明确失败
```

`/api/reader/access` 仍只交付访问决策，不交付正文；只有策略包含私有对象、允许格式且 Worker 已绑定 `PLATFORM_CONTENT` 时，它才返回 `delivery.available: true`。`/api/reader/content` 是唯一的正文读取路由：仅处理 `stream` / `preview`，每次请求重新验证会话，允许单段 Range，返回 `private, no-store` 的 EPUB/PDF 字节；它不会给浏览器对象键、签名 URL、令牌或下载模式。平台阅读页已经会为已收藏的平台版本请求访问决策，交付未配置时失败关闭；当前尚未把受保护 EPUB/PDF 字节接入可显示正文的渲染器，因此不得把“交付已准备”宣称为“已能阅读”。

正文进入平台前必须通过受控运营链路：`content_licenses` 记录许可与有效期，`content_source_records` 记录来源、审核与预期 SHA-256，`content_assets` 连接私有对象、来源与许可，`access_policies` 带许可和地区，`platform_content_audit_log` 保留发布/撤回记录。只有 service-role RPC 可在验证来源、哈希、许可和地区策略后发布、撤回或撤销；浏览器没有这些表、对象键或审计的读写权。即便不提供下载按钮，浏览器显示内容也不能构成绝对 DRM；产品应如实称为“在线阅读、不提供离线文件”，而不是承诺不可复制。

### 部署时的数据流与保存边界

```text
浏览器本地：原始 EPUB/PDF、封面、离线阅读状态
   ├─ OPFS / IndexedDB：原文件、即时进度、摘录、笔记、阅读统计
   └─ localStorage：当前未迁移的联网收藏、界面/阅读偏好

Cloudflare Worker：/api/catalog、AI/OCR 网关、短期公共书目缓存
   └─ 不保存原始书籍、不缓存选区文本、不会成为用户数据的事实来源

Supabase Postgres（目标云端同步层）：账户、书架元数据、进度、摘录、设置、设备、额度
   └─ 原书默认不上传；阅读统计与联网收藏须在 migration 与跨设备验收完成后才可宣称已同步
```

清除浏览器的站点数据会删除本机原书和本地状态。普通刷新、关闭标签页或重新打开浏览器不会删除它们。即使未来登录恢复云端元数据，用户仍需重新导入未开启明确云备份的原始文件。当前版本尚未完成阅读统计、世界书库收藏与全部偏好的可靠跨设备同步，因此应提供导出/导入并如实提示边界。

## 6. 云端 API 与 AI 安全

浏览器不直接调用 AI 或 OCR 供应商。网关负责隐藏密钥、限制成本和验证请求。

```text
POST /v1/explanations
POST /v1/ocr/pages
POST /v1/alignments
GET  /v1/usage
POST /v1/sync                 # 登录同步上线后启用
```

一次解释请求仅传递选中的短文本、少量上下文、源语言、目标语言与所需模式。禁止上传整本书，也不在普通日志中保存选区原文。

客户端应按“选区文本 + 上下文 + 目标语言 + 提示词版本”生成哈希，优先命中本地缓存，减少重复调用。

## 7. 面向消费者的身份、鉴权与权益

### 产品原则

- **可先试用，后注册**：用户第一次打开即可导入和本地阅读；请求云端 AI、OCR 或同步时才创建匿名身份。
- **本地数据优先于账号数据**：未登录时，书籍、进度和笔记仍在本地；注册不是阅读的前提，而是获得额度恢复、跨设备同步和付费权益的前提。
- **不把设备指纹当身份**：设备信息仅用于风险判断，不能作为找回账号、授予权益或精确计费的唯一依据。
- **权限默认收紧**：每一张服务端表都开启行级安全策略（RLS）；客户端使用公开发布密钥，`service_role` 等管理密钥只能存在于 Worker 的私密环境变量。

### 用户状态与允许操作

| 用户状态 | 身份凭据 | 可用能力 | 限制 |
| --- | --- | --- | --- |
| 本地访客 | 无服务端身份 | 导入、阅读、划线、笔记、导出 | 不可使用云端 AI/OCR，不可同步。 |
| 匿名试用者 | Supabase 匿名用户与短期会话 | 小额 AI/OCR 试用、查看当前用量 | 清除站点数据或退出后无法恢复；不能同步。 |
| 已注册用户 | 已验证邮箱魔法链接或 OAuth 身份 | 恢复权益、同步阅读数据、管理设备和导出 | 默认免费额度；受用量和风险规则约束。 |
| 已订阅用户 | 已注册身份 + 有效 `entitlement` | 更高额度、队列优先级、未来高级能力 | 权益只由服务端支付回调更新。 |
| 管理员/客服 | 独立后台身份 | 查询脱敏运营信息、处理用户请求 | 永不复用普通用户会话；最小权限、审计记录。 |

### 注册与账号迁移

首发使用 **邮箱魔法链接** 和 **Google / Apple OAuth**；不提供自建密码登录，减少密码泄露、重置和风控负担。邮箱必须验证后才视为永久账号。Apple 登录应在 iOS / macOS 的购买或登录场景中优先展示，以满足相应平台规则。

匿名试用者点击“保存并同步”时，可将当前匿名身份绑定邮箱或 OAuth 身份；绑定成功后保留同一个用户 ID，阅读数据无需搬运。若用户登录的是一个已有账号，客户端应展示冲突处理界面：默认合并本地书架、进度取更靠后位置、划线和笔记按唯一 ID 去重，冲突笔记保留两个副本并标记来源。此操作应可预览、可取消且只执行一次。

### 会话与 API 校验

```text
浏览器完成登录 / 匿名注册
 → Supabase 签发短期 access token 与刷新会话
 → 浏览器请求 Worker 时携带 Authorization: Bearer <access token>
 → Worker 用项目 JWKS 验证签名、issuer、audience、exp 和 sub
 → Worker 查询当前 entitlement / 额度并执行业务操作
```

- 前端只能读取自己的会话；不要把 access token 写入 URL、日志或分析事件。
- Worker 必须验证 JWT，不能只解析其中的 `sub`。使用 Supabase 的 JWKS 与成熟 JWT 库完成验签；遇到密钥轮换时尊重缓存失效策略。
- 高风险动作（改绑身份、导出云端数据、删除账号、支付状态变更）须要求最近登录或一次性邮件验证。
- 登出应撤销本设备会话并清除本地令牌；“退出并删除本地数据”需作为单独、明确的选项。

### 授权模型与 RLS

服务端数据采用 `user_id = auth.uid()` 作为所有权边界。普通客户端只能读取和写入自己的 `profiles`、`usage_ledger`、`sync_metadata` 和 `entitlements` 可见视图；不得直接修改额度、订阅状态、风控分数或账单记录。

匿名用户在数据库中也属于 `authenticated` 角色，因此 RLS 策略需要额外检查 JWT 的 `is_anonymous` 声明。例如：匿名用户只能读取自己的试用用量和创建有限的解释请求，不能创建云端同步记录、订阅或共享内容。所有 AI / OCR 扣费操作只允许通过 Worker 调用数据库函数，函数以原子事务完成“检查余额 → 扣减 → 写入账本”。

### 风控、设备与账户恢复

- 创建匿名用户、发送魔法链接、首次 AI/OCR 请求和支付入口均接入 Turnstile；令牌必须由 Worker 在服务端验证，且单次使用、五分钟内过期。
- 对匿名注册、解释、OCR 分别设置账号维度、会话维度与网络维度的限流；网络地址只作为辅助信号，不能作为唯一封禁或计费依据。
- 对高频新建匿名账号、重复选区、异常大图、短时间跨地域切换等行为提高风险等级，触发验证码、冷却期或人工复核，而非静默误封。
- 用户可在账户页查看最近活跃会话并撤销其他设备。首发不提供客服人工“凭设备找回匿名账号”的承诺。

### 权益、支付与数据权利

权益表是唯一的产品权限来源，字段至少包括 `user_id`、`plan`、`status`、`period_end`、`source` 和 `updated_at`。支付供应商的 webhook 先验证签名和事件幂等键，再由 Worker 写入权益；浏览器回传的“支付成功”只用于刷新界面，不能直接开通权益。

用户可导出同步数据、删除单本地书籍或发起账号删除。账号删除采用短暂宽限期：立刻注销会话和停止权益，宽限期后删除云端个人资料、同步元数据和用量关联信息；财务或反欺诈所必需的最小记录按隐私政策的期限保留。原始书籍文件默认不在云端，因此删除账号不会触碰用户本地文件。

## 8. 额度与反滥用

配额需要区分“快速拦截”和“准确记账”。

```text
请求到达
 → Worker：会话验证、人机验证、短窗口限流
 → Postgres 原子操作：确认并扣减当日余额
 → 调用 AI / OCR
 → 记录脱敏的状态、延迟与成本指标
```

Worker 的边缘限流用于抵御突发滥用；每日可用次数、订阅和计费状态必须以 Postgres 的原子事务为准。不要让多个存储系统同时成为额度的事实来源。

## 9. OCR 与译本对齐

### OCR

OCR 是异步、可取消的按页任务：客户端先将图片缩放并压缩，再只发送用户主动选择的当前页。小图片可直接转发给 OCR 服务；较大或耗时任务可使用短期对象存储与队列，完成后立即删除临时图片。

识别文字应以可编辑文本块或页面覆盖层展示。用户可以校正 OCR 错误后，再请求 AI 解释。

### 多译本对照

对齐分三级降级：

1. **章节对齐**：根据目录、标题和用户确认定位对应章节。
2. **段落对齐**：先使用本地规则生成候选；只有用户授权时才将少量段落发送给 AI 判断。
3. **自由对照**：低置信度或对齐失败时，保留两个独立滚动栏。

不同译本可能删节、合并章节或重排段落，因此不承诺全自动句对句对照。用户可修正的映射关系比错误的强制同步更可靠。

## 10. 隐私与可迁移性

- 默认本地存储；仅在解释或 OCR 时发送必要内容。
- 日志只保留脱敏的错误类型、状态码、时延与用量，不记录整书或完整选区。
- 提供本地书籍、笔记与缓存的删除入口。
- MVP 即提供阅读数据导出与导入：作品关系、进度、划线、笔记、AI 结果应可备份；原书文件可由用户自行另行备份。
- 同步功能上线后，书籍文件仍默认不上传；云端书籍备份必须由用户明确开启。

## 11. 分阶段实施

### 阶段 1：可靠的本地阅读器

- React + TypeScript + Vite PWA。
- EPUB 与文本型 PDF 阅读。
- OPFS + IndexedDB 持久化。
- 导入、删除、进度、划线、笔记和数据导出。
- 手动关联译本与独立双栏阅读。

### 阶段 2：受控 AI 解释

- Cloudflare Worker 网关。
- 匿名设备会话、人机验证、基础限流。
- Postgres 原子额度管理。
- 翻译、通俗解释、本地缓存与脱敏监控。

### 阶段 3：OCR 与半自动对齐

- 扫描页 OCR 与校对。
- 章节映射、段落候选及低置信度回退。
- 异步任务、取消、重试与临时文件清理。

### 阶段 4：账户与可选同步

- Supabase Auth。
- 修复共享 IndexedDB 适配器和跨设备“元数据已同步、原文件待重新导入”状态。

## 12. MVP 成功标准

第一个可公开试用版本只需稳定完成这个闭环：

```text
导入 EPUB 或文本 PDF
 → 离线继续阅读
 → 划线一段文本
 → 获得理解语言的翻译和解释
 → 保存摘录
 → 导出阅读数据
```

先验证此闭环的稳定性、成本和用户价值，再扩展 OCR、复杂格式和高精度多译本对齐。
