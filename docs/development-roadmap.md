# WorLibrary 从 0 到公网部署执行路线

本文将 WorLibrary 从当前静态 Demo 推进到可部署、可运营的 2C 世界图书馆产品。首发范围暂定为：本地导入 EPUB 与文本型 PDF、离线阅读、划线与笔记、匿名试用/注册、AI 翻译与通俗解释、阅读数据导出。

## 当前内测 MVP：1–2 周交付范围

本轮目标不是开放所有长期规划能力，而是交付一套可由真实用户连续试用的 Web 内测版。下列“纳入”项是本轮发布门槛；“延后”项不得阻塞内测，也不得在页面或对外说明中被表述为已经可用。

**纳入本轮内部技术验收：**本地 EPUB/PDF 导入、原书封面、翻页、阅读位置、划词翻译/解释、显式着色摘录、多译本关联与对照；合规世界书库检索与联网收藏；邮箱魔法链接登录；稳定账户之间同步书架元数据、阅读进度、摘录和必要偏好。另一设备收到本地导入书的元数据时，当前必须显示“需重新导入原书”，不得伪装为可打开的离线书。最后用两个独立浏览器 profile 完成真实 Supabase 验收。该技术验收不等于可公开发布的用户体验。

**明确延后：**高级端到端加密恢复码、Google/Apple 登录与匿名迁移、平台自有内容的运营发布/授权交付/下载、原生桌面和移动端、支付订阅、复杂并发冲突界面、以及完整的全球界面翻译包。内测保留中英文界面和全球 AI 理解语言选择。用户自导入书的“个人云书库”无感跨设备访问不再属于可无限延后的能力：在对外公开试用前必须完成。

## 0. 已确定方向与仍需产品确认的决策

第 6 项是已确定的产品方向；其余项目及个人云书库的配额、地区、删除与运营细节仍须在接入真实外部服务前确认：

1. 首发市场是海外、中国大陆，还是两者同时支持。
2. 首发格式只承诺 EPUB + 文本型 PDF。
3. 首发平台以桌面 Web 为主，还是同时优先移动浏览器。
4. AI/OCR 供应商、每日免费额度和月度成本上限。
5. 登录方式：邮箱魔法链接、Google、Apple，以及是否首发订阅付费。
6. 云端同步范围：登录用户首次明确同意后，书架元数据、进度、摘录、设置、阅读统计、联网收藏和自导入 EPUB/PDF 进入个人私有云书库；新设备登录后无需重新导入即可按需访问。默认使用托管加密以保障无感体验；高级端到端加密作为可选隐私模式，允许首次新设备要求恢复码或已登录设备确认。

## 1. 阶段与验收标准

### P1：工程化基础

- React + TypeScript + Vite + PWA 工程。
- ESLint、Prettier、类型检查、环境变量和 Git 忽略规则。
- 将现有静态 Demo 迁移到组件化应用，保留书库、阅读器、设置和 AI 面板。
- 配置本地开发、构建和测试命令。

验收：新开发者克隆仓库后可一条命令启动、检查、构建应用。

- [x] 将 Open Library 从页面内直连重构为 `WORLD_CATALOG_SOURCES` 适配器注册表。
- [x] 为每条收藏记录保存来源、来源记录 ID、外链与 `access.mode`；旧 Open Library 收藏自动迁移到 `catalog_only`。
- [x] 接入 Google Books 公开书目兜底，并将其 `viewability` 显式映射为书目、来源预览或公共领域外部入口。
- [ ] 接入第二个来源前，完成许可/条款、限流、来源标注、正文访问状态与失败隔离评审。
- [ ] 只为已验证的公共领域或授权正文来源展示对应入口；书目来源始终仅可跳转至原始来源。
- [ ] 将无语言限定的检索升级为 **Work（作品）聚合结果**：同一作品的原著与各语言 Edition 收敛在一张作品卡；原著以独立、强调的标识呈现，阅读版本列表按当前界面语言优先、其余语言随后排序。
- [ ] 语言筛选时只返回该语言的版本；“搜索原著”必须能按原题、作者和 `is_original` / `original_language` 查找，而不是把翻译题名误作原著。

### P1.6：Cloudflare 全球发布基础（进行中）

- [x] Worker 同域提供静态 SPA、`/api/health` 与合规的 `/api/catalog`。
- [x] 为无身份公共书目查询设置短期缓存，错误、健康检查和用户数据保持 `no-store`。
- [ ] 创建 Cloudflare 项目并用 `workers.dev` 完成真实上游连通性与全球可用性验收。
- [ ] 将 AI/OCR 网关从 Vercel 兼容入口迁移到 Worker，同时保留 JWT、额度与无共享缓存边界。

### P1.7：平台书库与合规阅读交付基础（后续阶段，不阻塞本轮内测）

- [x] 分离平台作品/版本、私有内容资产、地区访问策略、用户书架关系与服务端权益数据模型。
- [x] 建立不交付正文的 `/api/reader/access` 策略接口；受限内容必须经授权服务失败关闭。
- [x] 在书库显示真实可读状态，明确区分本地离线、在线、预览、来源阅读与仅书目。
- [x] 建立私有 R2 的 `/api/reader/content` Range 交付契约：每次请求复验会话，仅允许 EPUB/PDF stream/preview，不暴露对象键或下载 URL。
- [x] 建立许可、来源哈希审核、地区策略关联、审计和 service-role 发布/下架/撤销的运营迁移基础。
- [x] 建立服务端专用的运营角色数据边界和动态交付解析 SQL；发布策略会同步进入可解析状态。
- [x] Worker 仅在公开安全目录投影与私密平台访问策略拥有同一 `editionId` 时，才把已审核平台版本合并到世界书库并打开 WorLibrary 阅读器；未审核的联网“免费”结果继续只作为来源书目。
- [ ] 接入只在服务端可判定的运营人员角色检查，并建立管理员后台：内容审核、许可证/来源证据记录、平台版本发布、下架与撤销；普通用户永远没有这些入口或写权限。
- [ ] 部署内部内容 resolver（Service Binding）并让主 Worker 按数据库实时解析发布、地区、许可与权益；在完成前不得使用 SQL 发布流程对真实线上正文作出交付承诺。
- [x] 为已收藏的平台版本建立 WorLibrary 内阅读入口；交付不可用时明确失败关闭，不跳转第三方也不伪造正文。
- [ ] 接入首个书面许可明确的公共领域或开放许可正文来源，并保存许可证、版本哈希与来源审计信息。
- [x] 将受保护 EPUB/PDF 字节接入平台阅读器：带会话、无缓存地读入当前内存并完成基本翻页；不写入本地书库、不建对象 URL、不提供完整离线文件。
- [ ] 为平台阅读器补充授权会话内的位置恢复、可访问的目录/文本层和经许可的摘录策略；这些状态不得携带或持久化正文文件。
- [ ] 仅在获得明确下载许可时实现“下载到我的书库”；外部目录/预览来源不得出现下载入口。

### P1.8：用户跨设备数据与个人云书库

- [x] 确定用户书架、进度、摘录、统计与设置进入按用户隔离的数据表；正式目标为登录用户一次同意后自导入 EPUB/PDF 自动进入个人云书库。
- [x] 记录默认托管加密、可选端到端加密、分块对象存储、恢复码、配额、冲突、删除墓碑与平台内容隔离的技术基线，见 `docs/user-data-sync-architecture.md`。
- [x] 建立元数据同步的设备注册、变更日志、删除墓碑、键级设置与阅读统计事件数据库基础；仍不上传原书。
- [x] 建立仅 authenticated 稳定设备可调用的受控元数据 mutation/pull RPC：服务器分配 revision、处理幂等操作与删除墓碑，拒绝文件字节、对象键与正文定位字段；旧浏览器全表 REST 同步保持关闭。
- [ ] **内部技术验收：**将账户隔离 outbox/受控 RPC 接入页面写入和拉取路径，同步书架元数据、进度、摘录及必要偏好；远端本地书暂以“需重新导入原书”表示；完成双浏览器 profile 的真实 RLS、幂等、墓碑验收。
- [ ] **公开试用前核心：**部署私有用户对象桶、文件 manifest、受控上传、托管加密、账户配额、删除墓碑和新设备透明按需下载；用户仅登录即可在另一设备打开其个人云书库中的原书。
- [ ] **后续高级隐私：**补齐端到端加密、恢复码、已登录设备确认与复杂冲突 UI。

### P2：本地阅读器闭环

- OPFS 保存书籍文件，IndexedDB 保存结构化阅读数据。
- EPUB 目录、阅读、进度、字体和主题设置。
- 文本型 PDF 渲染、文本层选区与翻页。
- 书架、划线、笔记、删除和恢复阅读位置。
- 本地数据导出与导入。
- 存储空间不足、文件损坏和解析失败的恢复提示。

验收：导入 EPUB/PDF 后，刷新、关闭浏览器和断网仍可继续阅读并保留划线。

### P3：作品与多译本

- `Work`、`Edition`、`Highlight`、`Note`、`Alignment` 数据模型。
- 多语言版本手动关联，每个版本独立进度。
- [ ] 个人书库以作品聚合为默认视图：一部作品下归纳自导入、平台与联网收藏的各语言版本；原著单独标识，界面语言版本优先，来源和可读权限用标签区分。用户可切换“按作品 / 按版本”并按语言、原著、多译本、来源和阅读状态筛选，不能把不同语言机械拆成互相孤立的书架。
- 版本切换、双栏自由对照和章节映射建议。
- 低置信度时回退为两个独立滚动栏。

验收：英文原版和中文译本可以关联、切换、双栏阅读且进度互不覆盖。

### P4：2C 身份与云端（内测只承诺邮箱登录）

- local / staging / production 三套环境。
- Supabase Auth：匿名试用、邮箱魔法链接；Google/Apple 登录延后。
- 匿名身份升级、账号合并、RLS、JWT 验证和设备会话管理。当前版本尚未实现匿名身份升级：匿名试用仅限本机，不能排队或上传云同步；升级迁移必须在有明确合并与冲突策略后再开放。
- Worker API 网关、Turnstile、额度账本、权益表和账号删除。

验收：匿名用户可试用且不会触发云同步；完成受控升级迁移后才可注册并恢复已确认同步的数据；用户之间完全隔离；前端没有供应商密钥。

### P5：AI 翻译与解释

- 选区、上下文、源语言、理解语言的 API 协议。
- 翻译/解释结构化返回与本地缓存。
- 长度限制、超时、重试、幂等、成本熔断和供应商故障提示。
- 脱敏日志与模型版本记录。

验收：划线后稳定得到解释，重复请求命中缓存且不重复扣费。

### P6：OCR 与高级对齐

- 扫描 PDF 当前页 OCR、文字校对和异步任务。
- 图片大小/像素上限、临时对象清理和可取消任务。
- 章节与段落对齐候选、置信度和人工修正。
- CBZ、MOBI 作为实验性格式逐步加入。

### P7：公网部署与运维

- 域名、DNS、TLS、CORS、CSP、安全响应头。
- GitHub Actions：检查、测试、预览部署、生产发布。
- 数据库 migration 版本化，禁止直接修改生产表。
- 发布前后冒烟测试、代码回滚、数据库前向修复。
- 监控、告警、备份、恢复演练和密钥轮换。

### P8：公开试用

- 桌面/移动浏览器、弱网/断网、大文件和损坏文件测试。
- 无障碍、深色模式、字号行距、键盘阅读。
- 越权、JWT、额度、恶意文件和支付回调安全测试。
- 隐私政策、服务条款、版权投诉、客服与滥用处置流程。

## 2. 内测发布门槛

内部技术预览只承诺以下闭环：

```text
导入 EPUB / 文本 PDF
 → 本地离线阅读
 → 划线和笔记
 → 邮箱魔法链接登录（匿名仅限本机）
 → AI 翻译与解释
 → 已登录账户的元数据同步
 → 新设备“需重新导入原书”的明确临时边界
```

该技术预览完成后，才能进入个人云书库实现；在此之前不得把它包装成面对普通用户的完整跨设备产品。公开试用的发布门槛必须额外包含“同一账户在新设备仅登录即可看到并按需打开自导入书籍”，以及文件访问、配额、删除、RLS 和对象私有性的真实验收。OCR、MOBI、CBZ、自动段落对齐、平台正文交付、付费订阅和原生客户端在上述闭环稳定后再启用。

## 3. 当前执行顺序

1. 完成账户中心：私密头像菜单、账户/数据入口与退出登录；服务端建立普通用户、社区审核员、客服支持员和平台管理员的角色隔离。角色不能由前端、公开资料或 JWT claim 决定，管理员支持会话后置。
2. 补齐公开身份资料：独立 `public_profiles` 投影、可校验的公开昵称、可选头像/简介和默认关闭的社区主页；认证邮箱、私有书架、阅读位置、私人摘录、原书文件、设备和角色绝不进入该投影。头像使用专用受控媒体桶，上传需类型/尺寸/内容校验；先完成 RLS、对象策略、撤销公开状态和双账户隔离验收，再开放个人主页或社区内容。
3. 接入受控元数据同步的页面写入、顺序 flush 与拉取合并，保持匿名会话严格本机化。
4. 为远端本地导入书实现不可打开的“需重新导入原书”临时状态，并同步书架元数据、进度、摘录和必要偏好。
5. 在真实 Supabase 项目中使用两个独立浏览器 profile 验证 RLS、幂等、删除墓碑、断网重放和路由恢复。
6. 设计并实现个人云书库：独立私有对象桶、manifest、受控上传、托管加密、按账户配额、透明按需下载及“仅移除此设备 / 从云端删除”交互。
7. 用两个独立设备/profile 验收：仅登录后书架可见、点击即可恢复阅读、断点续传、不越权、删除立即失效，且不暴露长期对象 URL 或密钥。
8. 在账户与个人数据边界稳定后，开发作品书评、段落感想、剧透/举报/拉黑、实体书借阅，以及仅面向获得明确许可内容的数字借阅；普通用户自导入的版权文件不得成为他人线上可读文件。
9. 完成内测 Cloudflare 环境的翻译、目录、登录与同步冒烟；个人云书库验收通过后才邀请外部用户。
10. 后续再进入高级端到端加密、平台内容运营交付和原生客户端。
